# 轻量图像档案与报告接入制作计划

> 状态：`draft`。本计划替代“逐站高保真场景生图先行”的制作方法。最终产品仍是互动网页；图像用于提供证据、氛围与节奏，文字排版承载主要叙事和研究内容。

## 制作转向

### 停止作为前置门槛的工作

- 不再要求每个观察站先完成一张高保真、全景式、可直接复刻的场景图。
- 不再为统一视觉而给每站补造建筑、植物、人物或完整空间。
- 不以拟人化物件的戏剧动作承担站内主要内容。

### 新的展示逻辑

```text
真实照片 / 现场材料
  -> 最小化图像蒸馏或裁切
  -> 可复用的 zine / 研究档案版式
  -> 对话、田野旁注、趣事或研究摘录
  -> 可点击来源与延伸阅读
```

1. **图像是证据和情绪锚点**：每个章节使用 1-3 张处理后的照片、局部裁切、材质扫描感画面或照片蒸馏图，不制造全景还原。
2. **排版是叙事引擎**：对话、田野旁注、研究摘录、统计限定和来源状态由 HTML/CSS 呈现，不能烘焙进图像。
3. **动效是阅读节奏**：照片层显现、裁切滑入、纸张展开、段落推进、轻微颗粒/光影/材料位移；不需要 Three.js 才能成立。
4. **物件是索引，不是主角**：可作为页码标记、边缘小图、转场图章或悬停触发；主要阅读仍是人、行动、对话、感悟和研究材料。

## 视觉工具选择

只安装和测试一个工具，再决定是否扩展。不要同时安装九个第三方 skill。

| 工具 | 适配判断 | 建议用途 | 不建议用途 |
| --- | --- | --- | --- |
| `yangcodingmaster/photo-distill` | 推荐优先试用；使用 HTML/CSS/SVG 蒸馏真实照片，不依赖生图模型 | 单张现场照的极简构图、封面、章节视觉锚点 | 承担全文排版、生成事实性新物件 |
| `Evianis/travel-photo-abstraction` | 推荐第二候选；适合稀疏编辑化处理 | 石阶、树根、桥、水、夯土等局部的抽象档案图 | 人物对话场景、文化物件的精确重绘 |
| `wnby/photo-relic-editorial` | 可选；适合静谧的纸质记忆层 | 资料室、研究摘录、实拍证据页 | 全站统一主风格，避免过度怀旧化 |
| zine / poster 系列 | 仅在输出可编辑 HTML/CSS 或可拆分素材时试用 | 章节封面、研究卡版式灵感 | 直接生成完整网页、图内生成中文正文 |
| `daily-photo-playground`、pixel/poster、破坏性 photo skill | 不作为主风格 | 后续单页实验 | 主线档案；高饱和或强破坏会压低证据可读性 |

**首个技术验证**：只试 `photo-distill`，用一张不含可识别人物的杨家堂或松庄照片产出一个可编辑 HTML/CSS 章节视觉。验收标准是“保留原照片可识别来源、无新增对象、能嵌入现有 React 页面”。验证失败就停止，不继续堆 skill。

## 内容接入规则

每一个报告摘录必须进入数据层，不直接复制进组件：

```json
{
  "id": "claim-bq-001",
  "reportId": "observation-report-2026-08",
  "stationId": "banqiao-lan-teacher",
  "sectionRef": "二、核心研究发现（四）",
  "pageRef": "待补页码",
  "claimSummary": "本次观察样本中，村民的创新多表现为微小调整。",
  "excerpt": "经项目负责人核对后的短摘录",
  "sourceStatus": "public-source",
  "reviewStatus": "pending-owner-review",
  "scopeNote": "仅代表本次 23 份观察样本，不外推为全部村庄或畲族地区结论"
}
```

### 四种文字模块

| 模块 | 长度 | 视觉位置 | 依据 |
| --- | ---: | --- | --- |
| 田野一句 | 30-80 字 | 章节开头、照片旁 | `field-note` |
| 对话整理 | 60-180 字，分段推进 | 对话纸带/阅读层 | `oral-account` 或 `field-note` |
| 研究摘录 | 100-220 字 | zine 折页、资料卡 | 报告 `claim`，附范围说明 |
| 方法/限制 | 30-100 字 | 资料室、统计卡底部 | 报告元数据与局限 |

## 后续制作顺序

### 1. 先做报告入库，不做视觉

- 建立 `src/data/reports/`：报告元数据、章节/页码映射、原文摘录、审核状态。
- 从两份 DOCX 中提取候选 `claim`；PDF 只补方法和页码映射。
- 由项目负责人逐条选定可公开的 `claim`，避免自动摘要直接上线。

### 2. 建立一个可复用的“档案阅读站”组件

- 页面状态：封面视觉 -> 阅读块 -> 来源折页 -> 返回索引。
- 组件只读取 `station`、`content`、`claim`、`asset` 数据，不写死村名或故事。
- 用 CSS 实现纸张、布局、滚动与过渡；Three.js 只保留给可选数字标本，非主流程依赖。

### 3. 做一个“照片蒸馏”技术验证

- 选择一张无可识别人物的照片。
- 仅安装/试用一个 skill：`photo-distill`。
- 将结果以本地 HTML/CSS 或 SVG 模块接入 React；不接受只给位图且无法适配的方案。
- 决定是否引入 `travel-photo-abstraction` 作为第二种处理法。

### 4. 先完成两个文字最强的样板站

1. `BQ-02 兰老师的现场讲述`：测试 `oral-account`、人物风格化重绘、资料范围标记与标本链接。
2. `SZ-02 诉土桌边`：测试作者感悟、店主交流整理、材料局部与权限状态。

两站通过后，其他六站只需填数据和挑选图像锚点，不再单独走完整视觉定稿。

### 5. 再做全站索引与资料室

- 首页使用低多边形/几何方位的轻量总览，不再要求真实村庄漫游。
- 资料室提供报告索引、方法限制、全文文件入口和每条摘录的来源位置。
- 报告 PDF/DOCX 是否能公开下载，由单独授权字段控制。

## 新验收标准

- 任一研究结论均能显示报告、章节/页码、审核状态和适用范围。
- 任一照片蒸馏图仍能回链到原始照片；没有新增可识别对象。
- 任一对话都区分 `field-note`、`oral-account`、`creative` 与研究摘录。
- 关闭动画或静音后仍可完成阅读。
- 两个样板站完成后，新增站点不需要重新设计页面结构。

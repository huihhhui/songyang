# 协作与交接协议

## 目的

本协议将“总控决策”“视觉定稿”“工程实施”拆开，避免以对话记忆替代项目记忆。唯一长期依据是 `docs/v2/` 中带版本与状态的文档；任何对话都必须重新读取其被指定的文件，不能默认记得此前结论。

## 三类工作位置

| 工作位置 | 可以决定 | 不可以决定 | 输入 | 输出 |
| --- | --- | --- | --- | --- |
| 总控决策（当前对话） | 叙事节奏、证据边界、场景元素、视觉合同、跨场景冲突、冻结/退回 | 未冻结资产的批量生产、直接铺开实现 | 研究材料、问题、视觉交接包 | 决策台账、场景约束卡、冻结包 |
| 视觉定稿对话 | 在冻结包内探索构图、材质、光影、无 UI 场景、网页效果图、动效分镜 | 新增可识别对象、改变场景功能、把候选写为事实 | 当前冻结包及其指定参考 | 候选图、资产拆分、问题清单、视觉交接包 |
| 工程实施对话 | 用已冻结设计实现网页、测试、截图对照、报告技术限制 | 替代视觉定稿、补写素材、改写内容边界 | 冻结视觉包、数据与组件规范 | 可运行页面、测试、差异清单 |

## 问题回流

1. 任何涉及“该元素能不能出现”“场景应松或密”“是否有素材依据”“影响其他站”的问题，回到总控决策。
2. 已确认元素的构图、质感、光影、分层和候选图比较，在视觉定稿对话解决。
3. 动效、性能、响应式或可访问性是否可实现，先由工程实施报告，再由总控决策裁定是否改设计。
4. 视觉定稿对话遇到无法从冻结包判断的问题，必须输出为“待总控裁定”，不得自行补全。

## 状态定义

| 状态 | 含义 | 允许动作 |
| --- | --- | --- |
| `draft` | 草案，等待总控或用户审阅 | 可讨论，不生成正式资产 |
| `approved-for-exploration` | 可据此生成候选图 | 只能在边界内探索 |
| `visual-frozen` | 构图与资产角色已冻结 | 可交工程实现 |
| `implemented` | 已进入网页代码 | 只能修 bug 或经总控重新开启 |
| `superseded` | 已被后续决定替代 | 不再作为输入 |

## 冻结包格式

每轮视觉工作都必须使用单独的冻结包，内容不得只存在于聊天记录中。

```text

状态：approved-for-exploration / visual-frozen
规范版本与日期：
本轮唯一目标：
适用页面或场景：
必须读取的文档：

已确认的可识别元素：
可抽象化的表现：
禁止新增元素：
禁止宣称的空间或历史关系：

叙事功能 / 阅读节奏 / 信息密度：
必须保留的界面规则：
本轮产物：
不产出：

```

## 视觉交接包格式

视觉定稿对话返回时必须附带以下字段，未回答的字段视为待定：

```text
冻结包 ID：
使用的输入文件：
本轮候选图：路径或链接 + 用途
每张图中的可识别元素及其来源：
新增但未确认的元素：无 / 列表
不可复用或需删除的元素：
生成资产与代码 UI 的拆分：
动效建议与静态降级：
待总控裁定问题：
```

## 工作纪律

- 生成图、效果图、网页截图都不是事实依据；事实依据仍是素材、授权登记和来源状态。
- 允许画面通过光、影、水、风、纸张、材质与节奏变丰富，但不允许借此添加可被辨认的无来源对象。
- 视觉定稿不可将观察者当作站内叙事主角。视觉稿必须标明主要阅读内容是对话、现场观察、成员感悟、趣事，或有准确说明义务的资料卡。
- 带 UI 的效果图只用于视觉验收，正式网页中的文字、按钮、来源和权限状态必须由数据和代码输出。
- 每次总控确认后，在 `visual/00_视觉定稿工作簿.md` 追加决策条目；视觉对话重新开始时只读取最新冻结包和引用文档。

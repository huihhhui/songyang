# 视觉定稿与场景约束流程

## 目的

本规范用于在网页实施前冻结视觉方向、各观察站的叙事节奏与资产边界。它补充而不替代 `00_项目简报.md`、`01_设计决策与禁止项.md`、`04_视觉风格规范.md` 和 `05_交互与页面流程.md`。

最终交付是可访问的网页，不是单张概念图。生图只用于场景与局部资产；网页 UI、文本、来源状态、授权状态、响应式排版和交互控件由代码实现。

## 已确认的冻结原则

1. 每个观察站都必须按自身叙事功能、阅读节奏与信息密度设计，不以“统一丰富度”套用所有场景。
2. 所有可识别的建筑、植物、器物、人物、纹样、空间关系均必须有素材或数据来源。缺失依据时宁可留白，不补造事实性元素。
3. 统一的是田野图鉴、民艺标本与纸质档案的视觉语言；不统一每站的物件数量、画面密度、色彩强度或镜头距离。
4. 画面丰富度可以来自已确认对象的局部、材质、光影、留白、动效和可点击的观察层，不能靠添加无关物件填满画面。
5. 生成图不烘焙 UI 文案、按钮、来源标签或重要交互状态。带 UI 的效果图仅作为网页复刻参照，不作为直接上线素材。
6. 动效服务于观察：说明水、风、光、翻页或物件反应；不可替代事实内容，不可妨碍阅读，必须可在静态状态下理解页面。
7. 观察者是视觉引子与代替性的旁观者。每站的阅读重心优先是人的对话、现场观察、成员感悟与趣事；只有有准确说明义务的文化材料、展板或标本才以资料卡为主角。
8. 每个正式观察站至少定稿两个状态：**观察态**以空间、物件和环境动作建立进入；**阅读态**以对话纸带、田野旁注、趣事分镜或资料卡承载主要内容。资料型场景可由阅读态占更大比例，物件不可在两个状态中持续占据视觉中心。

## 场景约束卡

每个观察站在出图、建模或编码前必须建立一张场景约束卡。未填写的字段代表未知，不可由生成工具自行补全。

```text
场景 ID：
村落 / 观察站：
叙事功能：进入 / 停顿 / 转场 / 重点阅读 / 收束
阅读节奏：慢 / 中 / 快
信息密度：低 / 中 / 高（说明原因）
观众注意力：
主要叙事内容与来源状态：
观察者在本场景的功能：开场 / 引导 / 转场 / 趣事注释 / 不出现
主要叙事内容与来源状态：
观察者在本场景的功能：开场 / 引导 / 转场 / 趣事注释 / 不出现

已确认的可识别元素：
可抽象化元素（仅限材质、光、风、水、影等）：
不展示但已知的元素：
禁止新增元素：
可呈现的空间关系：
禁止宣称的空间关系：

镜头与构图：
光影与材质重点：
交互对象与触发方式：
动效对象、目的、循环时长：
证据层位置与来源状态：
生成资产清单：
代码 UI 清单：
待核验项：
```

### 审核问题

- 每个可识别元素能否回链到素材、数据或明确的创作化标记？
- 这个场景在完整浏览节奏中承担什么作用？
- 人、观察、感悟或趣事是否是主要阅读内容，而非观察者的独白？
- 人、观察、感悟或趣事是否是主要阅读内容，而非观察者的独白？
- 删掉一个元素后，是否反而更准确？
- 丰富度是否来自观察关系，而不是无关陈设？
- 页面静止时是否仍能读懂？

## 已确认示例：松庄溪中桃子

| 项目 | 冻结内容 |
| --- | --- |
| 组合 | 溪水、桃子、石拱桥 |
| 叙事功能 | 在整体流程中提供松弛但可驻足的观察段，不等同于信息缺失或空白页 |
| 可丰富的方式 | 水面与湿石的材料层次、光影变化、桃子随水流的轻微互动、局部观察层与安静的环境动效 |
| 可识别元素边界 | 不添加无来源的墙体、民居、店铺、人物、额外植物或其他村落反复使用的建筑元素 |
| 空间边界 | 只呈现已确认的溪水、桃子与石拱桥关系；不暗示完整村庄布局 |
| 文字边界 | 场景主画面不以额外说明文字填满；需要的来源、旁注与阅读内容由可展开的代码 UI 承载 |
| 观察者功能 | 瓦片乌龟只负责把视线带到水边动作与桃子，不承担传说说明或场景结论 |
| 观察者功能 | 瓦片乌龟只负责把视线带到水边动作与桃子，不承担传说说明或场景结论 |

## 视觉定稿产出

在进入高保真网页实施前，视觉定稿对话必须交付以下内容：

1. 全局视觉合同：色板、字体、纸档案层、证据层、材质和禁止项。
2. 三村叙事节奏表：标记每站为进入、停顿、转场、重点阅读或收束，并说明信息密度。
3. 每站场景约束卡：按照本规范填写并审阅。
4. 无 UI 的关键场景定稿：用于确认构图、物件、材质与可分层资产。
5. 网页效果图：档案总览、村落章节，以及每个观察站的观察态与阅读态；阅读态应明确表现对话、旁注、趣事或资料卡的主次。需含桌面和手机构图。
6. 资产拆分表：逐项标记代码 UI、生成资产、实拍证据、待授权资产和不可公开资产。
7. 动效分镜表：触发条件、对象、目的、时长、循环、静态降级与静音/减弱策略。

## 实施交接顺序

```text
三村叙事节奏表
  -> 场景约束卡审核
  -> 无 UI 场景与局部资产定稿
  -> 带 UI 网页效果图定稿
  -> 资产拆分与动效分镜
  -> React / Three.js / CSS 实施
  -> 浏览器截图与定稿图逐项对照
```

实施前必须冻结“可识别元素”和“禁止新增元素”。实施中发现素材不足时，退回场景约束卡降级处理，不以生成图补写事实。

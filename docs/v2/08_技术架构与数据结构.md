# 技术架构与数据结构

## 实施原则

旧 Demo 已明确弃用并移出项目。v2 直接使用项目根入口与 `src/`，继续使用 React、Three.js、React Three Fiber 与 Vite，避免无必要的重型依赖。

项目采用离线/在线混合发布：全部必要资源必须本地打包；线上部署仅提供静态文件，不引入运行时必需的后端或第三方数据服务。

## 建议模块

```text
src/
  app/           路由与全局状态
  data/          villages, stations, content, assets, artifacts
  scenes/        村落章节和观察站三维场景
  narrative/     对话、趣事、证据状态
  archive/       数字标本实验室
  ui/            档案总览、卡片、对话纸带、导航
```

## 最小数据模型

```json
{
  "stationId": "yangjiatang-couple-tree",
  "villageId": "yangjiatang",
  "sourceFolder": "28，27，50N 119，32，34E",
  "observerId": "couple-camphor",
  "contentIds": ["note-01", "artifact-01"],
  "evidenceAssetIds": ["photo-03", "photo-04"],
  "rightsStatus": "pending"
}
```

每个 `content` 条目必须携带 `type`、`sourceStatus`、`body`、`assetIds` 与 `rightsStatus`。涉及人物或回忆性对话时，还必须携带 `attributionMode`，值为 `field-note`、`oral-account`、`onsite-exhibit`、`creative`、`verified-quote` 或 `none`。作者旁注还必须携带 `authorId`、`authorDisplayName`、`authorVisibility` 与 `portraitConsent`。首发禁止使用 `verified-quote`，除非日后补充明确授权和原始记录。组件只消费数据，不内嵌特定村名、故事或人物姓名。

观察者数据还必须携带 `displayName`（艺术名）、`sourceObjectName`（真实物件名）和 `sourceFolder`。任何畲族语言装饰须携带 `languageSourceStatus`；只有 `verified` 状态允许渲染为文字，其他状态使用图形纹样占位。

## 内容成熟度与后续调研报告

作者感悟尚未写入时，条目应保存为 `contentStatus: "pending-author-note"`，正文可以为空或使用内部占位，不能提前生成正式叙事。后续组员调研报告接入后，原始报告应保存为独立文档记录；页面内容使用可追溯摘录，不直接将长篇专业文本塞进观察站主流程。

建议字段：`reportId`、`sectionRef`、`pageRef`、`claimSummary`、`excerpt`、`reviewStatus`。每条专业结论必须能回链到报告的章节或页码。

## 性能基线

- 首次只加载总览所需的缩略资源；章节和实验室按需加载。
- 图片生成缩略版本，原图仅在对照或放大查看时加载。
- 三维环境低多边形，重复植被采用实例化或合并策略。
- 点云应设置点数上限和降级策略，移动设备默认关闭高密度模式。
